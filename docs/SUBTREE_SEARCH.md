# PathSeek 目录子树搜索（开发分支）

## 语法与兼容性

| 输入 | 语义 |
| --- | --- |
| `fir/se/thi` | 旧模式：连续层级，不能越过 `second` |
| `fir/ so file` | 新模式：先定位 `first`，在所有后代层级查找名称同时匹配 `so`、`file` 的文件/目录 |
| `fir/se/ .ts$` | 先定位 `first/second`，递归查找后代中以 `.ts` 结尾的名称 |
| `fir/se//.ts$` | 与上一行相同，`//` 是快捷标记 |
| `raypath/ ` | 定位目录并递归列出已索引后代 |
| `raypath/.ts$` | **旧模式不变**：`raypath` 仅作为末尾直接父目录的模糊匹配条件 |
| `dyc/ dec` | 模糊匹配中文目录“第一次”，再递归搜索名称拼音 `dec` |

只有 `/ `（斜杠后空格）及 `//` 启动子树模式。独立空格仍用于 fzf AND；无斜杠时始终只匹配自身文件/目录名称。`.ts$` 是 fzf 的后缀语法；`*.ts` 属于 Shell Glob，`.*ts` 属于正则表达式，当前不解释成通配符。

## 目录选择方式

1. 普通列表中先上下高亮真实目录，输入 `/ ` 或 `//` 时优先尝试锁定此前高亮的目录；如果它是匹配路径的直接子目录，也允许锁定该子目录。
2. 也可对高亮目录直接执行 `Search Within This Folder` Action，尝试使用 Tab 快捷键。该操作先对**一个选定项目**调用 `stat` 确认是目录，不重新扫描目录树。
3. 没有可用高亮目录时，从既有索引推断候选目录：**恰好一个**自动选定；多个则列出供选择（最多 50 条，超过上限提示细化表达式）；无匹配时显示提示。截断列表绝不被误认为唯一。
4. 通过 Tab 或 `Search Within This Folder` Action 选定目录时，搜索框会**用完整的绝对目录路径替换旧查询**，并在末尾保留 `/ `，例如 `/Users/me/workspace/a/project/ `。因此不再携带先前的末尾搜索关键词，后续输入的新词仅搜索该真实目录的所有后代。即使多个目录同名，也能从搜索框中辨别精确作用域。通过 `Leave Folder Scope` 退出。

Raycast 提供 `List.onSelectionChange` 和 `Action.shortcut`，因此可以尝试在键入标记时读取高亮项。无修饰键 Tab 是否被搜索框优先消费，需要在 macOS Raycast 客户端中实测；若 Tab 不生效，Action Panel 仍可以完成同样的操作。

## 实现、安全及性能边界

- 全程复用已存在的 v3 压缩索引和原生 fzf 管道；不会运行 `fd`、跟随软链接、重新扫描磁盘、建立第二份索引或启动常驻进程。
- 目录候选从索引记录的祖先路径推断，使用原有逐段模糊及拼音匹配。限制检查缓存和候选列表大小，避免对 87 万路径构造无界目录集合。
- 选定范围使用严格的 `/` 边界：范围 `/projects/first` 不会误包含 `/projects/first-other`。只返回选定目录的后代，根目录本身不作为结果。
- 对选择性软链接目录保留索引中的可见别名路径，不把别名重新转换成真实目标路径。
- 中文原文、拼音首字母与全拼、Smart Case 和 fzf Extended Search 的现有行为保留。范围内末级还可使用既有的连续层级查询。
- 候选自动发现不做任何磁盘 `stat`，因此无子项且索引目录记录没有尾部 `/` 的空目录可能不能被自动推断；可使用普通搜索结果的 Action 选择。
- 第一次目录定位可能需要遍历整个索引；候选过多时仍需要用户输入更具体的路径。性能及 UI 交互应在实际 Raycast 中验收。

## 验收

测试覆盖 `/ ` / `//` 解析、旧 `/` 路径语义、精确目录范围边界、唯一/多选/过多候选、中文拼音、软链接别名、目录多层后代和 fzf 集成。

继续使用固定的完整基准命令验证规模与软链接规则：

```bash
npm run benchmark:standalone -- "$HOME" \
  --shortcuts "$HOME/Symlinks" \
  --hidden --quality 7 --runs 5 --compare
```

当前基准主要覆盖原有查询负载。后续可在相同脚本内增加子树专属负载，不新增重复的完整性能基准脚本。

## 本轮交互修正

- 原来选择 `Search Within This Folder` 时，如果当前搜索已经使用 `/ ` 或 `//`，代码会继续使用整个旧查询，导致旧关键词残留。现在 Action 与 Tab 都重新从当前选定目录开始，清空末尾关键词。
- 选中相同 basename 的两个目录，进入后的查询文本现在不同：`/work/project-a/src/ ` 与 `/work/project-b/src/ `。搜索范围由完整路径锁定，不再依赖目录名称重新模糊定位。
- 用户直接粘贴绝对目录加 `/ ` 的查询也会按索引中**精确**目录作用域处理；无需 `fd` 扫描。
- Raycast 的 `List.searchText` 接口不提供调整光标位置或文本选区的选项。如果通过 Cmd+K 的 Action 仍出现宿主将新查询文字高亮选中的情况，需要在 macOS 客户端反馈；这与之前旧查询残留问题不同。
