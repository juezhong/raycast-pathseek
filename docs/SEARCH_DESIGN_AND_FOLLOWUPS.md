# PathSeek 搜索设计与后续优化记录

> 状态：已完成当前版本的原生 fzf 多级模糊路径、无条件拼音匹配和流式性能修复；后续功能先评估，**不在本次合并中更改搜索语义**。

## 当前已实现、不可回退的规则

- 只有输入中包含 `/` 才进入路径模式。未含 `/` 时，只以文件/目录的**自身名称**参与 fzf 搜索，不允许父目录名称造成误命中。
- 路径模式按**连续**父目录级别匹配：`fir/se/thi` 可匹配 `first/second/third` 中的目录 `third`；`fir/thi` 不可跨过 `second`。路径层级与末尾目标仍支持模糊匹配，不能把末尾查询理解为指定完整文件名。
- 普通多级模糊路径由原生 `fzf --scheme=path` 匹配、评分与排序，同时做层级约束；含 Extended Search 运算符的查询走兼容的逐段过滤及最终名称 fzf 处理。
- 所有查询均支持原名、大小写规则、中文原文、拼音首字母与全拼；**不根据用户查询是否为 ASCII、有无操作符决定是否关闭拼音**。可根据候选记录是否确实需要拼音来避免不必要转换。
- 搜索结果全部来自索引中的真实文件或目录，按真实路径去重，保留取消、资源上限、结果数量上限。
- 软件的选择性目录软链接展开使用 `discoverSelectiveSymlinks` 与 `AliasPathMapper`；常规和快捷目标扫描不启用 `fd --follow`。不增加第二份磁盘索引或常驻后台搜索服务。
- fzf Extended Search 并不是完整正则表达式或 Shell Glob。例：名称后缀查询为 `.ts$`，而非 `*.ts` 或 `.*ts`。

## 本轮性能优化过程（真实 macOS 约 87 万条索引）

固定验收命令及临时目录审计方式见 [PERFORMANCE_BENCHMARK.md](./PERFORMANCE_BENCHMARK.md)。全部查询仅生成独立的测试索引，不使用、覆盖或清理 Raycast 正式索引。

| 阶段 | 主要改动 | 常见字符搜索 P50 | 无结果搜索 P50 | 结论 |
| --- | --- | ---: | ---: | --- |
| 开始 | 原有统一字符串候选处理 | 1425.52 ms | 1430.52 ms | 明显性能回退 |
| 第一轮 | ASCII basename 直接复用原始 Buffer 字节 | 1188.59 ms | 1153.33 ms | 延迟下降约 17%–19%，保留 |
| 第二轮 | fzf 输入端增加 64 KiB 批量推送 | 1248.12 ms | 1175.80 ms | 当时未真正批量生效 |
| 分段诊断 | 在预热轮次统计候选、输出批数和阶段时间 | 1177.74 ms | 1207.48 ms | 871,510 条记录对应 871,510 次输出；定位解码器单记录推送 |
| 解码器修复 | PathPrefixDecoder 以约 64 KiB 合并完整 NUL 记录 | **552.18 ms** | **534.82 ms** | 约 871,662 条记录变成 3,629 批；大幅改善 |

最后一次同一机器的其他 P50：文件名 544.01ms，多级路径 467.82ms，拼音路径 460.78ms。解码器改造后，普通搜索预热轮次的 `transformSyncWallMs` 约 217–229ms，此前约 843–909ms；`bytesSentToFzf` 约 137MB，故减少流写入调用而非减少索引覆盖范围。

**不能忽略的限制：**上述是不同时间的真实目录单次基准，非固定数据集隔离变量的 A/B 实验；目录和缓存状态可能变化。最后一次进程树合计 RSS 采样峰值约 810.8MB（773.2MiB），仍可能漏掉短峰或 OS 文件缓存。此前存在 8GiB 内存异常的历史，任何优化都必须保留进程树 RSS 和索引构建阶段验证。

## 暂缓进一步优化的建议

1. 暂时保持现有的 PathPrefixDecoder + 输入转换双层批处理，不再盲目修改批次大小；如果要调整，先证明新 P50/P95 与 RSS 数据具有可复现收益。
2. 继续记录区分实际 IO/解压、Node 转换、fzf 输入、fzf 退出阶段的诊断数据；分段时间重叠不可直接相加。避免把测量开销带入正式 5 轮延迟。
3. 下次实测严格保持 `--shortcuts "$HOME/Symlinks" --hidden --quality 7 --runs 5 --compare`，观察真实目录中文/拼音的正确性与极端大目录的 CPU、内存峰值。
4. 性能收益趋于有限后优先关注功能验收、排序质量以及取消操作时的资源回收，不能因性能变动破坏原名、拼音和文件/目录的统一处理。

## 后续需求评估：目录子树搜索（**未实现**）

当前语法 `raypath/.ts$` **仅搜索模糊匹配到的 raypath 父目录的直接子项**；目录若存在于多个位置也可能匹配到多个同名/相似目录。目录筛选是相对层级模糊匹配，不是绝对路径锁定。当前不支持跳过任意祖先层级，不支持 Glob `*.ts`、正则 `.*ts`。

### 推荐候选：显式双斜杠进入子树模式

- 保持现有 `raypath/.ts$` 的直接子项语义不变；
- 未来可设计 `raypath//.ts$` 表示：先模糊选择 `raypath` 目录，再对其**全部后代**的文件/目录名称做 fzf 后缀搜索；`raypath//ts` 对任意层级后代名称模糊匹配 `ts`。
- `//` **现在会报错**，目前只是候选新语法，绝不能宣称已支持。这仍然只有 `/` 触发路径模式，不与 `*.ts` 通配符混淆。
- 如果选择 `raypath/**/.ts$`（`**` 作为**完整目录段**的显式通配层级），则更接近 Shell Glob 的目录递归习惯，但需明确它不代表通用 Glob 或正则。

### 可行性与代价

- **中等工作量**：现有 `parseFuzzyPathQuery`、`compileFuzzyParentPathMatcher` 与 `createPinyinFilterInput` 可以增加独立的子树模式而不改索引格式；需要针对候选祖先逐级识别目录范围，结果的最终名称仍交由同一 fzf。
- 新模式扫描全索引仍是 `O(N)`，针对每个候选检查祖先需 `O(depth)` 的额外计算，可能明显慢于当前只校验末尾 N 层的方式。避免递归扫描磁盘、每层启动 fzf、无界缓存和额外索引。若目录名匹配过宽，必须限制输出和内存。
- 首次进入子树时应定义**同名目录范围**：保留全部模糊匹配候选目录，还是先锁定用户选择的某个真实目录。单纯模糊词 `raypath` 可能命中多个目录，不能暗自假定唯一。
- 如后续确实需要 `*.ts`，应单独评估支持 Shell Glob、后缀查询快捷语法或完整正则的产品成本与性能影响；当前 `.ts$` 为原生 fzf 后缀表达式。
- 验收必须覆盖 `first/second/third` 跳级、目录本身与文件、中文/拼音、符号链接别名、否定与锚点、索引规模超过 80 万条时的 P50/P95/RSS，以及普通搜索路径模式的完全向后兼容。

## 合并原则

本次只合并已完成的搜索功能与性能修复。**双斜杠子树模式、Glob/正则扩展均尚未实现，也不在本次 PR 的行为变更内。**
